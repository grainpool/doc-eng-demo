PHASE 03 — PROJECTS, FILES, LIMITS, UI SHELL.

Phase 02 is complete and verified: contracts, fact registry, D1 schema, and `/api/product-truth` with T1 + T3 tiers.

Build Relay's workspace surface. This is the first phase with a user-visible product.

SCOPE

1. Projects — `POST /api/projects`, `GET /api/projects`, `GET /api/projects/:id`. Fields: id, name, description,
   `state` (`active` | `archived`), created/updated. There is one demo workspace; a signed cookie
   (`RELAY_DEMO_COOKIE_SECRET` via `wrangler secret put`) identifies the demo user. That is the entire auth model —
   do not build signup, sessions, or roles (`constraints.md` §1).

2. File upload — `POST /api/projects/:id/files` (multipart). In order:
   - validate extension against the supported-type facts, and size against `limit.upload.csv.max_bytes`, using
     `relay-api/src/limits.ts` as the SINGLE enforcement point created in Phase 02;
   - on rejection return `{ error: { code, copy_id, field? } }` — never a hand-written sentence;
   - stream to R2 at `files/{projectId}/{fileId}/{filename}`;
   - compute sha256, byte size, and (by parsing the header + counting rows with a streaming reader, not by loading the
     whole file) `column_count` and `row_count`;
   - insert the `file` row. Also `GET /api/projects/:id/files` and `GET /api/files/:id`.

3. Copy registry, first pass — lives in the ESTATE repo at `estate/in-product-copy/*.json` (repo-2-relative:
   `in-product-copy/*.json`), imported by `relay-web` through the submodule path at build time. Plus a
   `t(id, vars?)` helper.
   It lives in repo 2 because in-product copy is part of the documentation estate that Concord reconciles, and Concord
   may only write to repo 2. A merged copy patch will not reach the running app until the submodule pin is bumped —
   that lag is intentional and documentable, not a bug to design around. Entries needed now:
   empty states, the uploader's help text, both rejection messages, project labels. Interpolation for the human-readable
   size limit. The formal `CopyEntry` schema and the `references_facts` field arrive in Phase 08; for now each entry
   needs at least `id`, `kind`, `text`, `surface_location`. Every user-visible string in `relay-web` must already come
   from here.

4. UI — React SPA screens: project list, create-project, project detail with file list and uploader. Include real
   empty, loading, and error states — they are documentation surfaces later, not polish.

   VISUAL STYLE — check for `design/theme.json` at the repo root before writing any styling. It was placed there
   ahead of this phase.
   - If it exists: read `design/README.md` alongside it first — it tells you which parts of the file are the
     operator's literal spec (`elementStyles`, verbatim, do not alter) versus derived extensions built to cover UI
     chrome the content-only spec didn't address (`palette`, `componentStyles`). Apply `elementStyles` to rendered
     content (empty-state copy, help text, any markdown-like text) and `componentStyles`/`palette` to the project
     list, uploader, buttons, and inputs you're building now. The README also lists the exact contrast ratios already
     verified for the derived colors — if you combine tokens into a pairing not listed there (a new hover state, a
     new tint), verify contrast the same way before shipping rather than assuming it inherits safety from its
     neighbors.
   - If it does NOT exist: do not invent a brand, logo, or colour system — keep the UI plain, legible, and neutral,
     exactly as before.
   Either way: this phase does not need a design system built beyond what the theme file or the neutral default
   already gives you. Don't add component variants, spacing scales, or tokens the theme file doesn't call for.

TESTS (required)
- `relay-api/test/files.test.ts`: over-limit upload rejected with a `copy_id`; unsupported extension rejected with a
  DIFFERENT code; a valid upload records sha256, byte size, row count, and column count correctly for a fixture CSV.
- `relay-web/test/no-literal-copy.test.ts`: a source scan over `relay-web` finds no user-visible literal in JSX text
  nodes. Make it fail first on a deliberately planted literal, then remove the literal.
- Edge cases from `validation.md` §7 that apply now: empty CSV, single-column CSV, duplicate column names, BOM, CRLF
  line endings (I am on Windows and will produce these), a quoted value containing a comma.

HARD RULES
- The size limit is enforced in exactly one place. Later phases depend on there being one enforcement point that is
  simultaneously the authoritative source of the `limit.upload.csv.max_bytes` fact.
- No hardcoded user-visible strings anywhere in `relay-web` (`constraints.md` §AP8).
- No analysis, no artifacts, no CLI, no chat. Not yet.
- Do not add an ORM. `env.DB.prepare()` with readable SQL (`constraints.md` §1).

are each rejected with distinct codes and registry-sourced messages. `pnpm test` green.
